# Mission 57 engine limit audit

Verified against branch `mission-57-engine`, based on Mission 56 commit `a6dd1074`. This is a source audit, not an iPhone runtime measurement.

| Limit | Owning source and observed behavior | Current connected-world status |
| --- | --- | --- |
| Player positions | `include/types.h` stores `MarioState.pos` and `vel` as `Vec3f`; `forwardVel` is `f32`. Collision surfaces still store three `Vec3s` vertices. | Mission 57 adds signed-64-bit **region metadata** and checked conversion to the current area-local `s16` window. It does not widen Mario or object physics. |
| World boundary and partition | `src/engine/surface_partition.h` selects stock `±8192`, 16×16 cells or opt-in `[-32768,32768)`, 64×64 cells, each 1024 units. `surface_collision.c` previously cast float positions to `s16` before bounds checking. | Connected queries now reject out-of-window X/Z before casting. Stock builds retain their original behavior, including parallel-universe coordinate wrapping. The dense grid remains a scalability limit. |
| Static/dynamic collision | `src/engine/surface_load.c` owns two dense partitions and shared static/dynamic pools. The opt-in pool has 8192 `Surface` and 32768 `SurfaceNode` slots; stock has 2300/7000. `clear_dynamic_surfaces` rewinds the counters each tick. | Pool allocation and triangle indices now have effective guards. A separately owned region mesh can link/unlink its own stable nodes into the existing static partition without consuming the rewindable dynamic pool. No general-purpose sparse partition exists yet. |
| Collision input format | `include/surface_terrains.h` emits `s16` vertex/count/index streams. `get_area_terrain_size` and the legacy loader have no external byte length; the dynamic-object transform uses a 600-word stack buffer (`surface_load.c`). | Legacy index and object vertex-count checks reject invalid references; the new region descriptor uses explicit vertex/triangle counts and validates the whole mesh before activation. Arbitrary malformed legacy streams still cannot be proven safe without a length-bearing format. |
| Connected Castle terrain | `levels/castle_grounds/areas/1/collision.inc.c` appends forest vertices/triangles to one global array; `connected_world/registry.inc.c` composes static render lists. | Existing forest is unchanged. New region collision and render lists can be registered independently. The existing authored forest is still part of the legacy array, so this migration is incomplete. |
| Objects and activation | `src/game/object_list_processor.h` gives 240 objects, or 960 with `NODRAWINGDISTANCE`. `spawn_object.c` initializes roughly 1000-unit collision and 2000/4000-unit drawing distances; `behavior_script.c` activates per-object by Mario distance. | The new region manager carries an owner tag only. It does not yet unload/reload region-owned actors or revise object pool limits. |
| Level/area lifetime | `src/game/level_update.c` still processes warps and `area_update_objects`; `src/game/area.c` loads one `TERRAIN` stream per active area. | Region activation happens before the ordinary object/Mario update and does not call a warp. Region resources are reset on area teardown. Existing level transitions remain unchanged. |
| Camera and clipping | Castle geo uses a 20,000-unit far plane (`levels/castle_grounds/areas/1/geo.inc.c`); `GraphNodePerspective.near/far` are `s16` (`src/engine/graph_node.h`). Camera positions are area-local floats. | A generated opaque-list hook culls registered regions conservatively by camera-to-AABB distance. The normal geo renderer still performs projection clipping. This is not full frustum culling or a far-plane redesign. |
| Metal resources | `src/pc/gfx/gfx_metal.m` uses `CAMetalLayer.nextDrawable`, per-draw vertex buffers, an 8192-entry texture table, and command-buffer presentation. | Mission 57 does not change Metal resource ownership or batching. Region render lists must remain valid through area teardown; GPU memory and draw-call cost still require device measurement. |
| Precision beyond the local window | The engine's `s16` collision vertices and `f32` player/camera state prevent direct use of an arbitrarily large absolute origin. `f32` also loses fractional precision as magnitude grows. | Signed-64-bit coordinates represent region placement and allow an explicit active origin. To travel beyond one local `s16` window, a future atomic rebase must move Mario, camera, all active objects, kart/portal state, render transforms, and collision together between simulation ticks. No rebase is claimed here. |

## Required next boundary

Before attaching Hyrule Field as another resident region, convert its generated collision/geometry to a length-bearing region descriptor and register it from an area catalog. Test the rendered list and collision transform against the same origin. Add a second area-local window or coordinated origin rebase only when a route actually exceeds the current `[-32768,32768)` window. Preserve SM64 movement equations and BLJ while testing the rebase with extreme negative velocities.
