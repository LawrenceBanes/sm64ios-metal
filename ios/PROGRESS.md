### Mission 47 — texture cache rollover correctness

- Audit traced SM64 RDP `LOAD_BLOCK`/`LOAD_TILE` through `gfx_sp_tri1` → `gfx_texture_cache_lookup` → `gfx_rendering_api` texture selection/upload → Metal fragment binding. Texture IDs and hash nodes are long-lived cache entries; sampler state is cached on each node. Every raster batch gets a packed CPU vertex stream, copied into a new shared Metal buffer before encoding. The renderer uses normal `commandBuffer` creation, whose default retained-reference behavior keeps encoded resources alive until GPU completion; each texture upload allocates a replacement `MTLTexture` and uploads RGBA with `width * 4` row pitch. No in-place CPU/GPU vertex-buffer race was found. `gfx_sp_tri1` flushes pending triangles before changing draw state, and the Metal depth texture is matched to the current per-frame drawable dimensions and cleared each pass. Existing shared vertex-layout/shader tests cover input counts and optional UV/fog/alpha packing.
- Found a concrete cache arena bug inherited from the local upstream `origin/ios` reference: the 512-entry cache reset only rewound `pool_pos`. Hash buckets still pointed into the arena, and both active tile bindings also pointed into those reusable nodes. When slots were overwritten, stale hash chains could traverse a later generation and an active tile could keep selecting a Metal texture ID whose content had just been replaced for another texture. Which surface was affected depended on cache rollover timing and subsequent draws, matching intermittent terrain/object corruption.
- Fixed rollover by clearing every hash bucket before arena reuse, invalidating both active tile-node references, and retrying texture binding for both shader-used tiles before encoding. Retry is limited to two passes; if a required texture still cannot be restored, the affected triangle is skipped rather than sampling a stale binding. No per-draw GPU wait or change to the `CAMetalLayer.nextDrawable` presentation path was introduced.
- Added a C rollover regression that exercises the same production reset helper and proves old bucket roots and both active tile references are cleared before slot reuse. Source-level checks verify the draw path restores missing bindings before encoding and keeps diagnostics opt-in/rate-limited. The native diagnostic panel has a persistent `Tex log: OFF/ON` toggle; rollover logs are off by default and emit only the first four resets and then every sixteenth reset. The existing private Documents log/share path captures enabled events.
