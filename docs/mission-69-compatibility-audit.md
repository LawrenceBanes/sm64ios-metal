## OMM source/package shape

The public OMM source snapshot at commit `536b5ed0bc88fd777250d3701cb876029582a2a1` contains 193 files: 89 `.lua`, 13 `.bin`, one `.bhv`, 80 `.tex`, and 10 `.ogg`. It includes actors, data, sound, and textures directories. The Lua set contains paired `-32.lua` and `-64.lua` chunks. The chunks are PUC Lua 5.3; header byte 13 stores `sizeof(size_t)` and is `4` in `cappy-events-32.lua` and `8` in `cappy-events-64.lua`. The corresponding Mario hook files have the same split.

Upstream sorts mod files by relative path, runs root Lua files in that order, and checks each bytecode header against the current Lua ABI. A chunk with a different `size_t` width fails that script load, while the loop continues to subsequent scripts. Mission 68's loader instead treated every root script failure as a fatal mod startup failure. That made a valid pair of 32-bit and 64-bit files incompatible on 64-bit iOS even if the native-width script was present. The new loader preflight skips only exact Lua 5.3 chunks whose `size_t` width is 4 or 8 and differs from the current process, then emits a diagnostic and continues. Other malformed chunks still fail normally.

References: upstream [`mod.c`](https://github.com/coop-deluxe/sm64coopdx/blob/8cd6e5977d9f920d51ca71f2c61801d019ed79c6/src/pc/mods/mod.c), [`smlua.c`](https://github.com/coop-deluxe/sm64coopdx/blob/8cd6e5977d9f920d51ca71f2c61801d019ed79c6/src/pc/lua/smlua.c), and the [Lua hook reference](https://github.com/coop-deluxe/sm64coopdx/blob/main/docs/lua/guides/hooks.md).

As a reference probe, the official upstream `hide-and-seek.lua` source reads and writes `m.marioObj.header.gfx.node.flags` and passes `m.marioObj.header.gfx.cameraToObject` to `play_sound`. Those nested paths are now backed by live native userdata rather than copied snapshots. Common N64 controller masks (`A_BUTTON`, `D_JPAD`, the remaining pad masks, and `VALID_BUTTONS`) are exposed from this engine's actual input definitions; optional CoopDX-only X/Y controls are not fabricated. The native `djui_popup_create(message, lines)` adapter uses the upstream six-second lifetime, requested line count for bounded panel height, top-right placement, and notification sound, but draws through the port's HUD queue. It does not emulate CoopDX rich-color markup, popup transitions, or full DJUI themes; message length, line count, command budget, and active popup count are capped. See pinned upstream [`djui_popup.c`](https://github.com/coop-deluxe/sm64coopdx/blob/8cd6e5977d9f920d51ca71f2c61801d019ed79c6/src/pc/djui/djui_popup.c).

## DynOS `.bin` format and activation gap

Upstream's `DYNOSBIN` format starts with an eight-byte magic (`DYNOSBIN`), a little-endian 64-bit uncompressed byte count, and a zlib stream. The decompressed bytes form a sequence of typed records. The actor loader recognizes light variants, textures and texture lists, vertices, display lists, geolayouts, animations and animation tables, and dynamic graphics commands. CoopDX parses its textual DynOS source and resolves Gfx/GeoLayout symbols and N64 constants into native graph data before registering an asset with a model pool; an actor bundle is not a flat mesh blob that can be uploaded directly.

The unlicensed OMM source archive in `/tmp` contains 13 `.bin` actor files. All 13 carry the upstream header and decompress to the declared sizes. M69D decodes all 13 bundles, links native vertices/display lists/geolayouts, and registers six OMM sparkle models with mod-owned cleanup. The other actor roots still fail the validated GeoLayout/function subset. This is host-runtime evidence; Apple compilation and iPhone rendering are not established. Upstream references: [`dynos_bin_compress.cpp`](https://github.com/coop-deluxe/sm64coopdx/blob/main/data/dynos_bin_compress.cpp), [`dynos.cpp.h` record types](https://github.com/coop-deluxe/sm64coopdx/blob/main/data/dynos.cpp.h), [`dynos_bin_actor.cpp`](https://github.com/coop-deluxe/sm64coopdx/blob/main/data/dynos_bin_actor.cpp), [`dynos_bin_gfx.cpp`](https://github.com/coop-deluxe/sm64coopdx/blob/main/data/dynos_bin_gfx.cpp), [`dynos_bin_geo.cpp`](https://github.com/coop-deluxe/sm64coopdx/blob/main/data/dynos_bin_geo.cpp), and [`dynos_mgr_models.cpp`](https://github.com/coop-deluxe/sm64coopdx/blob/main/data/dynos_mgr_models.cpp).

## M69 changes in this checkpoint

- Skip only PUC Lua 5.3 bytecode with an opposite 4-byte/8-byte `size_t` width during root-script startup; report the skipped file and widths.
- Add a regression that generates matching and opposite-width bytecode and verifies only the native-width script changes Mario state while the mod remains enabled.
- Add optional `MOD_EXTERNAL_ROOT` support to `tests/mods/run_host_tests.sh` for inspecting private, already-extracted mods without storing their packages in the repository.
- Implement upstream `HOOK_BEFORE_PHYS_STEP` output semantics for ground, air, water, and hanging physics. The hook receives Mario state, `STEP_TYPE_*`, and the step argument; the first valid integer return skips native stepping and becomes its result. The matching step/result constants are exposed to Lua. Host coverage verifies each step kind, the air step argument, and first-output short circuit.
- Implement `HOOK_ALLOW_INTERACT` at the existing Mario interaction dispatch point. The native handler runs only when allowed; nil preserves the default allow state, boolean returns update it, callback errors disable only the failing hook, and the existing post-interaction event still receives the handler result. Host coverage exercises allow, deny, and nil behavior.
- Bind `perform_ground_step`, `perform_air_step`, and `perform_water_step` to the existing engine functions with upstream Lua argument and result shapes. The host fixture calls all three through Lua and checks the returned native step results and airborne step argument.
- Bind upstream `play_sound(soundBits, Vec3f)` to the existing native sound engine, and expose mutable engine-owned `gGlobalSoundSource` and `gDefaultSoundArgs` vectors. The host fixture verifies the sound ID and all three position coordinates received by the native function; the unmodified Achievements ZIP no longer reports `play_sound` as unsupported.
- Add an initial native HUD adapter for `FONT_NORMAL`, screen dimensions/resolution, color, text measurement/printing, and alpha rectangles. Commands are bounded to 256 primitives and 512 text bytes per frame, then rendered from `render_text_labels` through the existing RDP display-list route (which the Metal backend consumes). Lua argument errors and command-limit violations are explicit. Other DJUI fonts and texture rendering remain unsupported, and the queue has not been visually verified on iPhone.
- Add upstream N64 controller-mask constants, live `MarioState.marioObj.header.gfx.node.flags` read/write, and `header.gfx.cameraToObject` vector access. Add a bounded `djui_popup_create(message, lines)` adapter rendered through the native HUD queue, with upstream-style notification sound, lifetime, placement, per-mod cleanup, and explicit rich-color-markup diagnostics. Synthetic tests cover these paths; original possession ZIP execution is still blocked on obtaining the package and confirming its license.
- Return `nil` with a per-mod diagnostic for CoopDX mouse getters because the iOS touch controller has no pointer-compatible API yet. The tested Achievements script guards this case, so its gallery is non-interactive instead of raising a Lua error.
- Reproduce the numeric `BehaviorId` enum order from pinned upstream `include/behavior_table.h`; the extracted identifiers are kept in `tools/coopdx_behavior_ids.txt`. Local pointers are attached only for behavior symbols present in this engine. `Object.behavior` remains a behavior-script pointer, and the getters translate between pointers and CoopDX IDs. `obj_get_first`, `obj_get_next`, and behavior-filtered iteration skip deactivated objects and are bounded by the native object-pool capacity. `obj_mark_for_deletion` calls the engine lifecycle helper. These bindings do not implement native behavior replacement or object synchronization.
- Define `gGlobalSoundSource` in the native audio engine, matching the upstream zero-initialized global sound position.
- Extend the existing iOS workflow for `metal-validation/*` pushes so it runs a full iPhoneOS arm64 compile-only job; its IPA packaging/upload step explicitly excludes those branches.
- Extend the asset-free Xcode failure summary to include only validated linker symbol identifiers, while keeping raw Xcode output runner-local.

The original sandbox, ZIP validation, Lua API boundaries, existing native gameplay, and DynOS inactive status remain unchanged.
